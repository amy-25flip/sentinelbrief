## Review 1 — the reviewer agent, 2026-09-24 (Checkpoint 1)

Method: ran every check in HANDOFF myself, read all core code against the primary CERT-In PDF, probed the clock engine with adversarial inputs, re-extracted the PDF and compared it with the stored text, mutation-tested the benchmark, and read the CERT-In MSME extension notice (not previously read). Everything marked FIXED was fixed in this review and is covered by a test. Baseline before the review: 36 tests, 8 scenarios. After: 118 tests, 17 scenarios, mypy/ruff/format/validate all green.

### Fixed

- [major] [clock] `clock/engine.py` (old lines 46-78, 207-220). Annexure I was decided by substring keyword matching, and "no match" meant "not Annexure I". Evidence: input "Attacks on Application such as E-Governance, E-Commerce" and "Attack on servers such as Database, Mail and DNS" (both real Annexure I types x and vi) returned no deadline and "not annexure I", telling the user the 6-hour report does not apply. "cloud region power outage" returned a firm 6-hour deadline. Substring terms like `dos`, `iot`, `worm` match inside unrelated words. Fix: the 20 titles now live in `data/reference/annexure_i.json` (verbatim, test-checked against the source text); unambiguous named types match on word boundaries; ambiguous words only produce a "please confirm" suggestion; free text can never conclude "not reportable", only an explicit user attestation can. FIXED.
- [major] [clock+data] Retention duties were modelled as `relative` deadlines from `occurrence`. Evidence: a VPS provider with a known occurrence time was shown a "deadline" of 2031-09-19 (5 years from occurrence). Fix: new deadline kind `retention` (schema + model + data for Directions (iv), (v), (vi)); engine never computes an incident deadline from `retention`, `recurring` or `none`. Calendar durations (years/months) are refused for deadlines. FIXED.
- [major] [clock] Naive datetimes were silently read in the server's local timezone (`astimezone` on a naive value). On a UTC server a 09:00 IST input would shift the deadline by 5.5 hours. Fix: naive datetimes are rejected at construction and at evaluation. FIXED.
- [major] [clock] The law was evaluated "as of now": `law_snapshot_date=now`, `validity` intervals ignored, `repealed`/`superseded` status ignored. Evidence: an incident on 2021-01-05 (before the Directions took effect on 2022-06-27) got a CERT-In deadline. Fix: `evaluate(..., as_of)` defaults to the earliest known incident time and filters by `valid_from`/`valid_to`; result carries `law_as_of`. Brief section 5.3 / principle 5. FIXED.
- [major] [clock] Anchor logic sniffed `"cert-in" in obs_id.lower()`; any anchor other than noticing/occurrence/detection (awareness, publication, fixed_date) was silently skipped. Fix: joined triggers are data (`alternative_anchors`, earliest known wins); unsupported anchors and kinds become an Unknown, never a silent skip. FIXED.
- [major] [clock] A missing `data/obligations` silently loaded zero obligations, and an unrecognised entity class (e.g. "NBFC") silently produced "nothing applies". Fix: both raise. Obligations are validated against the Pydantic model on load. FIXED.
- [major] [clock] Conditions other than Annexure I ("CERT-In has issued a specific order", "as defined by Ministry of Finance") were ignored, so those obligations looked unconditionally applicable. Fix: surfaced as `conditions_unevaluated`. FIXED.
- [major] [web] `web/templates/incident.html` computed clocks with a hand-written JavaScript copy of the CERT-In logic (hard-coded 6h; ignored the entity class; treated "unknown" as applicable and showed a deadline; read `datetime-local` in the browser's timezone but labelled it IST), and its form posted via htmx to `/api/incident/clock`, which did not exist. HANDOFF described this as real-time server computation. Fix: real `POST /api/incident/clock` calls the engine; all client-side clock logic removed; form times are read as IST explicitly; JSON API requires an explicit UTC offset; the result fragment shows unknowns, caveats, ongoing duties, not-applicable reasons. Also vendored htmx (was an unpinned third-party CDN script without integrity check). FIXED.
- [major] [data] All 7 obligations were marked `verification: human_verified` with reviewer `antigravity-agent`. An AI review is not a human review (brief principle 4/section 5.2). Fix: relabelled `machine_checked`; the validator now rejects `human_verified` without a named human reviewer or with an AI-looking reviewer name. FIXED.
- [major] [provenance] Stored `.txt` was never verified against the PDF or its own metadata (`meta.text_sha256` was written but never checked); the file on disk had CRLF line endings so its bytes did not match the recorded hash; the extraction code was not in the repo, so nothing was reproducible from the raw files (principle 6). Fix: `extract/pdf_text.py` (deterministic, LF), `verify/raw_provenance.py` (manifest hashes, PDF hash, text hash, fresh re-extraction, orphan files) wired into `validate_all`; text regenerated and confirmed byte-identical to what the citations were validated against; `.gitattributes` added. FIXED.
- [major] [ingest] `BaseFetcher` wrote a manifest format incompatible with `data/raw/manifest.json` (running it would have corrupted the committed manifest), silently reset a corrupt manifest, overwrote a changed document in place (destroying the previous evidence, against brief section 7), used a made-up contact URL in its User-Agent, ignored robots.txt, retried 404s, and `CertinFetcher` used different filenames from the committed data. Fix: schema-conformant manifest, corrupt manifest raises, changed documents are archived (`<stem>.<sha8><ext>`, entry `superseded`), robots.txt honoured, configurable contact, 4xx not retried, filenames aligned; KEV/EPSS feeds do not hoard history. FIXED.
- [major] [benchmark] The scorer read only `regulators`, `deadlines` and the presence of unknowns; it ignored `expected.citations`, `expected.not_applicable`, the anchor name and unknown content, compared timestamps as `pred[:19] == exp[:19]` (drops the offset), and passed a scenario if unknowns were merely present. The "3/3 adversarial traps passed" claim therefore verified nothing about the traps. Labels were also wrong: `cert-in-government-org` listed Direction (iii) "comply with CERT-In orders" as applicable although its first paragraph names only "service provider/intermediary/data centre/body corporate", not government organisations; `cert-in-brought-to-notice` had noticing=brought-to-notice=10:00 so it could not distinguish the two anchors. Fix: scorer checks every label field with timezone-aware instants; labels corrected against the primary text; 9 adversarial scenarios added (17 total); mutation tests prove each reintroduced bug is caught; CLI exits non-zero on failure. FIXED.
- [major] [ci] CI would have been red: `ruff check src/ tests/` failed (I001), the benchmark job ran a module that does not exist (`python -m sentinelbrief.benchmark`), and `tests/test_clock.py` hard-coded `e:/SentinelBrief/data`, so on any other machine the engine loaded no obligations. HANDOFF said "All checks passed". Fix: relative paths, working benchmark command, ruff/format now also cover `benchmark/`. FIXED.
- [minor] [validate] `text_verbatim` not being an exact substring of the source was only a warning; the citation validator accepted a citation carrying either the expected hash or the text hash; an excerpt occurring twice with no char range passed. Fix: error / exact hash / error. FIXED.
- [minor] [evidence] Disclaimer claimed clock source and NTP status "are captured", but they are caller-declared defaults (`system`, `False`) never measured. Tail truncation of the log is undetectable from the file alone; timestamps could go backwards; a second writer could fork the chain; event type was not validated; the tamper tests only mutated in-memory objects. Fix: honest disclaimer, `verify(expected_head_hash, expected_count)`, monotonic-time check, stale-writer detection, event type validation, on-disk tamper tests. FIXED.
- [minor] [web] Obligation pages showed retention durations as "Deadline: P5Y (not applicable)". FIXED.
